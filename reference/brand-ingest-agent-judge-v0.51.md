# 브랜드 연결 — 에이전트 판정 층 설계안 (v0.51 제안)

> 대상: Freesm 데모(`KDX-brand-swap-demo.html`) + `api/ingest.js`
> 상태: **설계안 · 미구현.** 승인 후 착수.
> 한 줄 요약: 규칙 파이프라인을 그대로 두고, **근거가 약한 구간에서만** 에이전트를 심판으로 부른다. 에이전트는 색을 만들지 않고 **고르기만** 한다.

---

## 1. 지금 무엇이 규칙인가 (현행 정리)

브랜드 연결은 네 단계이고, 네 단계 모두 손으로 정한 규칙·임계값·공식으로만 돌아간다. 학습된 판단은 한 곳도 없다.

### 1.1 수집 — 소스마다 다른 경로, 결과는 같은 모양

| 소스 | 실행 위치 | 수집물 |
|---|---|---|
| URL | 서버 `api/ingest.js` `ingestUrl()` | HTML + 링크된 스타일시트 최대 6개, favicon·apple-touch-icon 최대 2개 |
| Figma | 서버 `ingestFigma()` | `files/{key}?depth=4` 트리를 순회해 SOLID 채움색·`fontFamily`·`cornerRadius`·`itemSpacing` |
| 북마클릿 | 대상 사이트 안 (`BMK_CODE`, `bv:3`) | `getComputedStyle` 실측 — 색 빈도·radius·padding·폰트·theme-color·브랜드 변수·그라디언트(선언 셀렉터 포함) |
| 파일 | 클라이언트 | SVG는 원문 파싱, 이미지는 캔버스 픽셀(`imgDominant` / 700×400 이상이면 `shotDominant`), 폰트 파일은 FontFace 등록 |
| 텍스트 | 클라이언트 | `extractHex()` · `font-family` 정규식 · `extractShape()` |

서버 응답 스키마는 고정되어 있다.

```
{ colors:[{hex,count,html}], fonts:[String], declared:[{hex,count,source}],
  shape:{radius,radiusTop,radiusPct,density,padTop,padPct},
  assets:[{label,type,b64}], gradients:[css원문], source }
```

### 1.2 정규화 — 고정 임계값 세 개

`validHex()`(서버) / `validHexC()`(클라이언트)가 동일한 규칙을 쓴다. **채도차 `max-min < 24`**, **최댓값 `< 35`**(너무 어두움), **최솟값 `> 238`**(너무 밝음)이면 브랜드색이 아니라고 보고 버린다. 선언된 값이라도 예외 없다.

### 1.3 판별 — 혼합 점수가 아니라 우선순위 계층 (`igResolve`)

```
1순위  선언   theme-color · msapplication-TileColor · --primary/--brand/--accent/point/key-color/main-color
2순위  로고   favicon · apple-touch-icon 의 주요색 (유채색 비율 ≥ 2%, 흑백 로고는 통과)
3순위  그라디언트  게이트를 통과한 그라디언트의 대표 정지점
4순위  사용통계  igScore 최고값 (폴백 전용)
```

`igScore()`는 이렇게 생겼다.

```js
eff   = html != null ? html*10 + max(0, count-html) : count      // 렌더된 화면의 색을 CSS 번들보다 ×10
score = √eff × (s/100)^1.2 × fitL × fitC
fitL  = max(.05, 1 - |l-45|/55)                                   // 명도 45 근처 선호
fitC  = .25 + .75 × min(1, max(0, (흰글자대비-1.15)/2.2))          // 소프트 하한 0.25
```

그라디언트는 `gradVerdicts()`가 줄마다 판정과 사유를 만들고, `igResolveGrad()`가 2패스(그라디언트를 뺀 Primary 확정 → 그 Primary를 잣대로 게이트)로 돌린다. 게이트는 맥락 셀렉터(`ctx=1/0/-1`), 휴 50° 정합, 근거량(2곳 이상 반복 또는 참조된 로고 SVG 안), SVG `url(#id)` 실제 참조 여부다.

형태는 `pickMode()` — 값을 버킷에 담고 **가장 많이 담긴 버킷**을 채택한다(중앙값 아님).

```
RAD_BUCKETS  sharp(<6)  default(6~14)  rounded(>14)      최소 표본 3
PAD_BUCKETS  compact(≤9) default(9~18) comfortable(≥18)  최소 표본 5
```

### 1.4 적용 — 결정적 램프 생성

`genRamp(seed)`가 시드를 HSL로 바꿔 8단계를 고정 곡선으로 찍는다(05·10·20 라이트 / 40 비비드 / 50 시드 / 55·60·70 다크). `applyCustomBrand()`가 `[data-brand="custom"]` 스코프에 CSS 변수로 주입하고, `contrastWhite()`로 p50의 흰 텍스트 대비를 계산해 AA 여부를 알린다.

## 2. 규칙이 이미 진 자리 — 왜 에이전트인가

코드 주석에 실패 기록이 남아 있고, 그 실패들의 성격이 같다. **"이게 브랜드의 것인가"는 빈도·위치·색 거리로 환원되지 않는다.**

- **네이버 핑크 사고(v0.47)** — 페이지 어딘가의 프로모션 그라디언트가 로고보다 앞선 Primary 후보가 됐다. 시스템에 "이 페이지에는 브랜드 그라디언트가 없다"는 상태 자체가 없었다. 계층 순서를 손으로 내려서 막았다.
- **`ad` 부분일치 과교정(v0.48)** — 반대 증거 정규식이 `.header`·`.shadow`·`.download`까지 잡아 정상 그라디언트를 통째로 기각했다. 정규식을 좁혀서 막았다.
- **스크린샷 그라디언트 추정 철회(v0.47 ⑧)** — "상단에 고채도 색이 여럿"은 컬러 아이콘 줄·태그 칩·썸네일이 모두 만드는 패턴이라, 픽셀 통계로는 판단이 불가능하다고 결론내고 기능을 걷어냈다.
- **스크린샷 신뢰도 게이트(v0.45)** — 전체 화면 픽셀 빈도로는 브랜드색을 못 찾는다는 걸 6종 실측으로 확인했고, 해상도를 올려도 결과가 바뀌지 않아 **구조적 한계**로 판정했다.

앞의 둘은 규칙을 고쳐서 막은 것이고, 뒤의 둘은 **규칙으로 못 풀어서 기능을 지운 것**이다. 지운 자리가 곧 에이전트가 들어갈 자리다. 스크린샷 한 장에서 "좌상단이 로고고 이 색이 브랜드색, 오른쪽 알록달록한 건 콘텐츠 썸네일"은 시각 판단으로는 쉬운 문제다.

## 3. 설계 원칙 (이걸 어기면 도입하지 않는 편이 낫다)

1. **적용 단계는 절대 에이전트에게 주지 않는다.** `genRamp`·`contrastWhite`·토큰 주입은 결정적이어야 한다. 같은 시드를 두 번 연결했을 때 다른 램프가 나오는 순간 이건 디자인 시스템이 아니라 제안 도구다.
2. **에이전트는 hex를 생성하지 않는다.** 이미 수집된 후보 배열의 **인덱스만** 반환한다. 최악의 경우도 "다른 후보를 골랐다"에 그친다. 환각 색이 토큰에 들어갈 경로를 구조적으로 없앤다.
3. **규칙이 이기는 구간에서는 부르지 않는다.** 사이트가 `theme-color`로 자기 브랜드색을 선언했으면 그보다 강한 증거는 없다. 에이전트는 **동점·저신뢰 구간의 심판**이지 1순위 판정자가 아니다.
4. **에이전트는 선택적 층이다.** API 키가 없거나, `file://`로 열었거나, 호출이 실패하면 **지금과 완전히 동일하게 동작**해야 한다. 규칙 경로를 지우지 않는다.
5. **판정 근거를 사람이 읽을 수 있게 남기고, 되돌릴 수 있게 한다.** 현재 UI가 이미 후보 스와치·그라디언트 나래비·기각 사유·수동 적용 버튼을 갖고 있으므로 그 위에 얹는다.

## 4. 아키텍처

### 4.1 엔드포인트 분리 — `/api/judge`

`api/ingest.js`에 옵션으로 붙이지 않고 **별도 함수로 분리**한다. 이유가 셋이다.

- `ingest`는 결정적이고 캐시 가능하지만 `judge`는 비결정적이고 **유료**다. 수명과 비용 성격이 다르면 엔드포인트를 나눈다.
- 북마클릿·파일·텍스트 경로는 서버 `ingest`를 거치지 않는다. `judge`가 분리되어 있어야 **모든 소스에서 같은 심판을 부를 수 있다.**
- 장애 격리 — judge가 죽어도 ingest는 산다.

### 4.2 호출 게이트 — 언제 부르는가

클라이언트 `igShow()` 직전, `igResolveGrad()` 결과를 보고 판단한다.

| 상황 | 에이전트 호출 |
|---|---|
| `declared.length > 0` (선언값 있음) | **부르지 않음** — 규칙 승 |
| 로고 마크로 확정, 그라디언트 판정 전원 명확 | 부르지 않음 |
| `basis`가 `CSS 사용 통계…`로 시작 (선언·로고 시그널 없음) | **호출** |
| 스크린샷 경로 `igShotConf`가 `mid` 또는 `low` | **호출**(비전) |
| 로고는 있는데 `gradVerdicts`에 `근거 부족`이 섞여 있음 | **호출**(그라디언트 판정만) |
| 파일 탭 SVG 업로드, 후보 3개 이상 | 호출 |

예상 호출률은 실제 사이트 기준 30~40% 수준이다. 잘 만든 사이트일수록 `theme-color`를 선언하고, 그런 사이트에서는 아예 부르지 않는다.

### 4.3 입력 페이로드 — 작게, 개인정보 없이

```json
{
  "host": "example.com",
  "candidates": [
    {"i":0,"hex":"#1245ba","src":"css","count":31,"html":3,"hsl":[221,82,40],"contrastWhite":8.1}
  ],
  "gradients": [
    {"i":0,"stops":["#fa7e1e","#d62976"],"src":"svg","ctx":1,"count":2,"verdict":"ok","why":"…"}
  ],
  "fonts": ["Pretendard","Noto Sans KR"],
  "shape": {"radius":"rounded","radiusTop":16,"radiusPct":62,
            "density":"default","padTop":12,"padPct":54},
  "images": [
    {"role":"logo","mime":"image/png","b64":"…"},
    {"role":"screenshot","mime":"image/jpeg","b64":"…"}
  ]
}
```

- `host`만 보내고 전체 URL·쿼리스트링은 보내지 않는다.
- 이미지는 **최대 2장, 각 512px 이하로 리사이즈**해서 보낸다(현재 `fetchAssets`가 이미 400KB 상한을 걸어둔다).
- 원본 HTML·CSS는 **보내지 않는다.** 이미 구조화된 후보만 보낸다 — 토큰이 싸고, 유출면이 작고, 에이전트가 새 hex를 만들 재료 자체를 주지 않는다.

### 4.4 출력 스키마 — 인덱스와 enum만

```json
{
  "primary": 2,
  "gradient": null,
  "radius": "rounded",
  "density": "default",
  "font": "Pretendard",
  "confidence": "high",
  "why": "좌상단 로고 마크와 CTA 버튼이 같은 남색 계열이고, 상위 후보인 주황은 프로모션 배너에만 나타납니다."
}
```

**서버 측 검증(이걸 통과 못 하면 전부 버리고 규칙 결과를 쓴다):**

- `primary` — 정수, `0 ≤ i < candidates.length`. 필수.
- `gradient` — 정수 또는 `null`. 범위 밖이면 `null`로 강등.
- `radius` — `sharp|default|rounded|null`, `density` — `compact|default|comfortable|null`.
- `font` — 입력 `fonts` 배열에 **문자열이 정확히 존재**할 때만 채택. 아니면 `null`.
- `confidence` — `high|mid|low`.
- `why` — 200자 상한으로 자르고 HTML 이스케이프(`igEsc`가 이미 있다).
- 응답 전체가 JSON이 아니거나 `primary`가 없으면 → **폴백**.

### 4.5 응답 반영

```
judge 성공 → cands 재정렬(에이전트가 고른 후보를 0번으로) → igShow(...)
             basis = "에이전트 판정 · " + why
             confidence==='low' 이면 autoApply 보류 (기존 shotConf low 처리와 동일)
judge 실패/타임아웃(6s)/키 없음 → 지금 그대로 igShow(...) + 아무 표시 없음
```

UI 변화는 최소로 둔다. `#igResultLab`의 판별 근거 문구가 바뀌고, 1순위 스와치 뱃지 옆에 `AI` 라벨이 붙고, **"규칙 판정으로 보기"** 토글 하나가 생긴다. 토글을 누르면 규칙이 고른 후보로 즉시 되돌아간다 — 되돌리기 경로가 없는 자동 판정은 넣지 않는다.

### 4.6 실패 사다리

```
API 키 없음        → judge 층 자체를 숨김(토글도 안 보임). 현행과 100% 동일
file:// 로컬       → 호출 안 함. igRemote와 같은 안내 문구 계열
6초 타임아웃       → 규칙 결과 유지, 조용히 넘어감(사용자를 기다리게 하지 않음)
스키마 위반        → 규칙 결과 유지 + 서버 로그에만 기록
rate limit / 5xx   → 규칙 결과 유지 + "에이전트 판정을 건너뛰었습니다" 한 줄
```

## 5. 서버 구현 스케치 (`api/judge.js`)

```js
// POST /api/judge   body: { host, candidates, gradients, fonts, shape, images }
// 응답: { ok:true, verdict:{...} }  또는  { ok:false, reason }
// 필요 환경변수: ANTHROPIC_API_KEY (Vercel 환경변수 — 코드에 넣지 않는다. FIGMA_TOKEN과 동일 취급)
module.exports = async (req, res) => {
  const key = process.env.ANTHROPIC_API_KEY;
  if (!key) return res.status(200).json({ ok:false, reason:'judge-disabled' });
  // 1. 입력 검증 — candidates ≤ 12, images ≤ 2, b64 합계 ≤ 1.5MB
  // 2. 모델 호출 (6초 AbortController)
  // 3. 출력 파싱 + 4.4의 검증 규칙 전량 적용
  // 4. 통과분만 verdict로 반환. 하나라도 어기면 ok:false
};
```

프롬프트 요지(전문은 구현 시 확정):

> 당신은 브랜드 아이덴티티 분석가입니다. 아래는 한 웹사이트에서 **규칙 기반으로 이미 수집한** 색·그라디언트·폰트·형태 통계입니다. 새로운 색을 제안하지 마십시오 — 반드시 주어진 후보 중에서 고르고, 인덱스로 답하십시오. 브랜드 색은 로고 마크·주요 CTA·헤더에 쓰이는 색이며, 프로모션 배너·콘텐츠 썸네일·차트·상태색(성공 초록·경고 빨강)은 브랜드 색이 아닙니다. 판단 근거를 한국어 두 문장 이내로 쓰십시오.

이미지가 있으면 같은 메시지에 붙여 **어느 후보가 로고에서 실제로 쓰였는지**를 보게 한다. 이게 픽셀 히스토그램이 못 하던 부분이다.

## 6. 단계별 도입 (한 번에 다 하지 않는다)

**1단계 — 색 판정만, 텍스트로.** 이미지 없이 후보 배열만 보낸다. 게이트는 `basis`가 `CSS 사용 통계`로 시작할 때만. 가장 싸고(이미지 없음) 가장 안전하며, 지금 가장 자주 틀리는 구간이다.

**2단계 — 비전 추가.** 로고 마크와 스크린샷을 붙인다. `igShotConf`가 `mid`/`low`인 경로가 여기서 살아난다. v0.45에서 "구조적 한계"로 판정한 그 구간이 대상이다.

**3단계 — 그라디언트·형태·폰트 판정.** 그라디언트 나래비의 `근거 부족` 줄에 대해 에이전트 소견을 한 줄씩 붙인다. 형태(곡률·간격)와 폰트는 규칙이 이미 꽤 맞으므로 마지막이다.

각 단계는 독립적으로 롤백 가능해야 한다.

## 7. 비용·지연

| 항목 | 예상 |
|---|---|
| 1단계(텍스트만) 입력 | 후보 12개 + 그라디언트 6개 ≈ 1.5K 토큰 |
| 2단계(이미지 2장) 입력 | + 512px 이미지 2장 ≈ 3K 토큰 |
| 출력 | 200 토큰 미만(스키마 강제) |
| 추가 지연 | 텍스트 1~2초 / 비전 2~4초 |
| 호출률 | 전체 연결의 30~40% (선언값 있는 사이트는 호출 안 함) |

지연을 사용자에게 숨기지 않는다 — `igMsg('브랜드 근거 확인 중…')`을 띄우고, 6초를 넘기면 규칙 결과로 그냥 진행한다.

## 8. 검증 계획 (`verify51.js`)

기존 회귀(`verify48.js` 그라디언트 게이트, `verify50.js` 화면 조립기, `verify45.js` 스크린샷)는 **전부 그대로 통과해야 한다.** 에이전트 층은 얹는 것이지 바꾸는 것이 아니다.

신규 케이스:

1. **게이트** — `declared`가 있는 mock 응답에서 judge 호출이 **일어나지 않음**(fetch 스파이).
2. **스키마 위반 폴백 6종** — 범위 밖 `primary`, 문자열 `primary`, 목록에 없는 `font`, enum 밖 `radius`, 400자 `why`, JSON 아닌 응답. 6종 모두 규칙 결과가 그대로 유지되고 화면에 에러가 뜨지 않아야 한다.
3. **hex 직접 반환 차단** — `{"primary":"#ff0000"}` 같은 응답이 토큰에 반영되지 않음.
4. **성공 경로** — `basis`에 `에이전트 판정`이 들어가고, 고른 후보가 0번으로 올라오고, `applyCustomBrand`가 그 hex로 호출됨.
5. **되돌리기** — "규칙 판정으로 보기" 토글이 규칙 1순위로 복귀시키고, `--brand-p50`이 원래 값으로 돌아감.
6. **키 없음 / 타임아웃 / 5xx** — 세 경우 모두 현행과 픽셀 동일하게 동작(스냅샷 비교).
7. **저신뢰 보류** — `confidence:"low"`면 자동 적용하지 않고 후보만 제시.

## 9. 열린 결정 (진행 전 확인 필요)

- **자동 호출 vs 버튼.** 게이트를 통과하면 자동으로 부를지, "AI로 다시 판별" 버튼을 두고 사람이 누를지. 자동이 매끄럽지만 비용이 사용자 손을 떠난다. **권장: 1단계는 자동(싸다), 2단계 비전은 버튼.**
- **결과 캐시.** 같은 호스트를 다시 연결할 때 판정을 재사용할지. 데모 특성상 같은 사이트를 반복 연결하는 시연이 많다. 인메모리 `Map(host → verdict)` 정도면 충분하고, 서버 캐시는 과하다.
- **모델 등급.** 텍스트 판정은 작은 모델로 충분할 가능성이 높다. 비전 판정만 상위 모델을 쓰는 이원화를 검토.
- **로고 이미지 전송 동의.** 사내 인트라넷 URL을 넣는 경우 로고가 외부로 나간다. 모달에 한 줄 고지를 넣을지, `host`만 보내는 텍스트 모드를 기본으로 할지.
- **`api/ingest.js`가 스크린샷을 만들지는 않는다.** v0.45에서 헤드리스 캡처는 봇 차단을 못 푼다고 결론냈으므로, 스크린샷 경로의 입력은 여전히 **사용자가 올린 이미지**뿐이다. 에이전트를 붙여도 이 제약은 그대로다.
